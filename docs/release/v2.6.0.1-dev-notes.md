### What's Changed

**Up to date with OrcaSlicer 2.6.0-dev** (445 upstream commits, to e2db7e5ef1). Upstream fixed seven bugs this fork had
been carrying its own fixes for, among them the prime tower missing from the first slice of a multi-filament print
(our report, OrcaSlicer/OrcaSlicer#15991), a crash when quitting or opening a project during a slice, and the Creator 5
Pro's chamber not heating with chamber control on. The fork now takes upstream's fixes.

**New and changed tools** (113 in the app's list, 117 with the bridge's own).

- **`add_primitive_object`** (new): a cube, cylinder, sphere, cone, disc or torus as a new object, as the canvas's Add
  Primitive does, at its default size or a size you give.
- **`order_objects`** (new): the plate menu's Order By (name, filament, height, size, ascending or descending). On a
  plate printed by object, the object list's order is the print order.
- **`get_scene_info`** reports a by-object plate's real print order (`print_order`), and says when the slicer prints an
  object later than its place in the list to avoid a collision.
- **`load_model`** takes `import_options` for STEP, AMF and CAD 3MF files: keep or clean up the original part names,
  sort them, load as an assembly or a single object (AMF: also separate objects).
- **`add_volume`** takes a primitive's `size`.
- **`get_config_values`** and **`apply_config`** say why a setting is unavailable ("Enable support or add raft layers
  to edit this setting.").
- **`apply_config`** refuses an excluded bed area whose edges cross, as the settings field does.
- **`set_plate_settings`**: renaming a plate whose G-code uses `{plate_name}` invalidates its slice, as the app's own
  rename does, and says so (`slice_invalidated`).
- **`send_to_printer`**: on a Flashforge with a material station, a printer profile with manual filament change starts
  with the station off, as the app's send dialog now does; a `material_mappings` list still uses it.

**Fixed**

- Loading a STEP, AMF or CAD 3MF file through MCP failed, and adding a primitive part added nothing: upstream's new
  import and size dialogs were answered Cancel. They are now answered with the saved options or the call's own.
- A plugin's request for network or file access is now always refused during an MCP call; only you grant it, in the
  Plugins dialog.
- `arrange_objects` on one plate reports and uses that plate's own print sequence, not the global one.

**Build**

- Every dependency is rebuilt (wxWidgets, OpenCV 4.14, libpng 1.6.59, expat 2.10.0; FreeType removed), so the first
  build after this release is long.
