### What's Changed

**Connect your AI app with no Python to install.** Preferences, MCP Clients, Connect now writes an entry that runs the
bridge with the Python OrcaMCP already ships, for Claude Desktop, Claude Code, Codex (desktop app, CLI and IDE
extension), Cursor, Windsurf, Cline and GitHub Copilot. Until now every entry ran `python3`, which failed on most
machines: macOS's own Python is too old for the bridge, and Windows' standard Python installer provides no `python3`.
On the Linux AppImage the entry uses your system's `python3` (3.9 or newer); Connect says so when there is none.

- **Existing entries are repaired for you.** The first launch of this version updates every `orca-slicer` entry
  OrcaMCP wrote, in every AI app's config, and again whenever the app moves. Only the command and its arguments
  change: your own settings in the entry (`env` with `ORCAMCP_TIMEOUT`, Codex's `env` table, a longer Codex timeout)
  are kept, the rest of each file is untouched and keeps its order, and an entry that runs another bridge is never
  touched.
- **Codex** gets `startup_timeout_sec = 20` and `tool_timeout_sec = 140`; its own 60 s cut off long calls.
- **Codex's config is read by a real TOML parser.** Connect and Disconnect still edit the file where it stands, so
  comments and layout survive, but every edit is checked before it is written: the result must parse and read the
  same as before everywhere except the `orca-slicer` entry. A config that is not valid TOML is left alone, with the
  line and column Codex would also stumble on. Disconnect removes every `[mcp_servers.orca-slicer.*]` table, wherever
  it stands.
- **Safer config writes.** Every config is written atomically under a temporary name of its own, keeps its permissions
  (applied before any content), and stays a link when it is one; a config you made read-only is refused, not
  replaced. A config OrcaMCP cannot edit safely (an unreadable file, a Codex entry as an inline table, dotted keys or
  an array of tables, a servers value that is not an object) is left alone and Connect says what to change. A
  rewritten JSON entry keeps its own keys, and its `env`, in your order.

**Up to date with OrcaSlicer 2.6.0-dev** (104 upstream commits, to 3838002bc8): painted modifiers (paint an area of a
part and give it its own settings), a brim filament setting, variable layer height shared across objects, volumetric
speeds, a sparse infill strategy, and a calibration filament picker. Upstream fixed one more bug this fork carried its
own fix for (a crash computing the shared printable area of a two-nozzle printer).

- MCP tools handle painted modifiers safely: they are reported as `painted_modifier`, take settings as a modifier does,
  and are refused, with the part to act on instead, where they follow their part (move, type change, repair, split,
  replace with a file). Deleting a part answers `deleted_painted_modifiers`, the ones that went with it. Adding and
  painting them from an agent comes next.
- Deleting or merging a filament slot renumbers the new brim filament, as it does support filaments.

**Fixed**

- `start_orca` found no OrcaMCP installed outside the default folder on Windows; it now reads the folder the installer
  recorded.
- The bridge runs on Python 3.9 (macOS's own).
