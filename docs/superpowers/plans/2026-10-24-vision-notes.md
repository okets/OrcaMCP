# Vision plan: notes for later tasks (written by V0)

## What V0 built (where to plug in)
- `OrcaMCPRenderRequest.{hpp,cpp}` (pure): `read_render_request(payload, error)` -> `RenderRequest` {plate_index, save_to_file, resolution, use_png, overlays, layer_view (null for 3D), views, contact_sheet}. `ViewRequest` {preset, preset_name, camera_position/target (as given, in input_frame), input_frame, fit (FitRequest Plate|Object{object_id}), fit_json}. Also `ShaderSettings` (+ `shader_settings_uniform_names()`, `is_default()`).
  Parser takes the PAYLOAD (the tool's arguments), not `{payload: ...}`. A new view key: parse it in `read_view`, store on ViewRequest.
- `OrcaMCPRenderSchema.cpp`: `render_plate_view_schema()` built from `overlays_schema()`, `layer_view_schema()`, `fit_schema()`, `view_schema()`, `views_schema()`; `render_plate_view_description()`. Views are strict (`additionalProperties: false`); `camera` declared as `{"type":"object"}`. Add each new view key to `view_schema()`; add a "sent back" case in test_mcp_tool_arguments.cpp ("render_plate_view views are strict...").
- Three steps in `OrcaMCPPlateUtils`: `PrepareRender(payload, RenderJob&)` (main thread; layer views answered here, returns non-null), `ComputeRender(job, stop)` runs `job.work` (HTTP thread), `DrawRender(job)` (main thread; checks `job.captured_objects` pointer+id first). `RenderJob` holds the request, `views` (ResolvedView: request, fit_box, camera_position, target in bed mm after plate_local conversion), plate_box, legacy_boxes, exclusion_regions. The handler is in OrcaMCPServer.cpp ("render_plate_view" registration); deadline = start + tool_wait_cap() - 5 s; `stop_at(deadline)` moved to OrcaMCPUiJob.hpp (inline), used by texture bake tools, repair_mesh and render.
  Old `RenderPlateView(params)` is gone.
- `RenderOptions` hooks (RenderThumbnail): `draw_volume(const GLVolume&, RenderPass&) -> bool`, `after_volumes` (vector of fn(RenderPass&), run with shader still in use), `shading` (ShaderSettings), `camera_frame` (optional CameraFrame: drawn with exactly those matrices; `out_camera->frame` is then that frame; viewport is NOT applied from it, caller keeps width/height equal). `RenderPass{view, projection, shader, plate_index}`.
- Shader `mcp_render` (resources/shaders/{110,140}/mcp_render.{vs,fs}): thumbnail + `clipping_plane` (frag, vec4), `use_light_dir`, `light_dir_eye`, `ambient`, `front_light` (vert). Registered in GLShadersManager right after thumbnail, OPTIONAL: failure is logged and dropped from the startup error list. RenderThumbnail falls back to `thumbnail` and sets `report->shader_fallback = true`; in that case ShaderSettings are NOT applied. V3/V4 must check `report.shader_fallback` and say in the answer that light/section could not be applied (or refuse), never silently ignore.
  The ES (SLIC3R_OPENGL_ES) prefix has no mcp_render files: falls back there.

## Deviations from the plan
- `fit` description changed to object_id; golden diff therefore also has that description text (plan said only additionalProperties, fit.object_id, camera).
- Parser errors for presets/camera/frame now come before the object-range/plate lookups (they are all read up front); each message is unchanged.
- A fit with both object_id and object_index differing is refused with: "fit.object_id and fit.object_index are the same number; send object_id only".
- `get_server_info` tool_examples and docs/tools/reference.md now say `fit: {object_id}`.
- CLAUDE.md probe CB paragraph and the Key Files rows are V8's (not written).
